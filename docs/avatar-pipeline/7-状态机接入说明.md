## R2. 第二轮接入（v1.2.0 → v1.3.0，新增 4 状态 + 过渡态可选）

### R2.1 新增的四个状态

用户在素材里追加了 4 张 Q 版新素材，`frames.json` 版本升到 `1.3.0`（22 状态，均 121f/24fps，
`frameW 360 / frameH 480`，扁平格式）。逐帧抽帧与接缝实测后确定接入方式：

| 状态 | 素材内容 | 首/末帧→idle | 优先级 | 触发入口 | 播完去哪 |
|---|---|---|---|---|---|
| `angry` | 叉腰闭眼憋气 → 站定 | 2.04% / 1.93% | 60（情绪） | 模型 `emotion='angry'`；本地连点 5 次 / 8s 内连续报错 | `idle` |
| `attention` | 举手示意"我在这里" → 放下 | 1.89% / 1.74% | 50（交互） | 模型 `emotion='attention'`；本地随机 55~125s，冷却 75s | `idle` |
| `stretch` | 伸懒腰打哈欠 → 站定 | 2.16% / 2.02% | 50（交互） | 模型 `emotion='stretch'`；本地随机 2~4 分钟，冷却 120s | `idle` |
| `drag_start` | 站立 → 被拎起悬空、惊恐脸红 | 入场 2.25% | 200（拖拽） | pointer 真正移动时（皮肤含此表才播） | **`drag`** 循环 |

**`stretch` 的定位变化（重要）**：第一轮曾因"语义与 `sleep_start` 重复 + 旧画风不混用"删掉
`stretch`。这次是**全新画风**的配套素材，且用户拍板为「独立动作，随机/闲置触发」——
它是清醒时舒展身体的动作，与 `sleep_start` 里"入眠前的伸腰"不是同一语义，也不共用素材。
因此重新加入，并同时提供本地随机触发与模型下发两条入口。

**`angry` / `attention` 用户均选「两者都要」**：既进 `PetEmotion` 白名单由模型下发，
也有本地事件/定时触发。`attention` 与 `wave` 语义刻意区分：前者"请注意我"，后者"你好/再见"。

### R2.2 过渡态可选（本轮架构要点）

用户明确的原则：**过渡态是可选的** —— 一个皮肤可以没有 `drag_start` / `sleep_start` /
`sleep_end`，只要循环动画（`drag` / `sleepy`）存在，就能直接进入循环态；过渡态存在时才
被放到正确位置串起来。

实现（`PetStage.vue` 的 `hasState()`）：`durations` 在 `PetAvatar` 加载 `frames.json` 后回填，
键集合即皮肤 manifest 的状态集合。加载空窗期按"内置皮肤含全部过渡态"处理（用户不可能在
那几毫秒内完成拖拽），避免首帧误判。三条降级路径：

| 过渡态 | 皮肤有 | 皮肤无 |
|---|---|---|
| `drag_start` | 拎起时先播惊恐起身（约 5s）→ `drag` 循环；松手随时打断 | 直接进 `drag` 循环（其第 0 帧即"被拎起"姿势） |
| `sleep_start` | 闲置到点播入眠动作 → `sleepy` | 直接硬切 `sleepy` 循环（首帧即睡姿） |
| `sleep_end` | 被交互叫醒播起床动作 → `idle` | 从 `sleepy` 直接硬切 `idle` |

降级路径不会切到缺素材的状态，因此 `SpriteRenderer.setState` 的 missing 告警不会因
"皮肤缺过渡态"而误报。拖拽过渡计时器 `dragStartTimer` 在松手时必被清除，不会把 idle 改回 drag。

### R2.3 接缝依据（为什么这样配过渡）

预乘 RGB+alpha 平均绝对差（与 §4.5 同一口径）：

- `angry`/`attention`/`stretch`：首/末帧→idle 全在 1.7%–2.2%，与现有一次性动作同档，
  沿用 `FADE_MS` 默认 160ms，无需单独标定。
- `drag_start`：首帧→idle 2.25%（与 idle 同构图，硬切自然）；末帧→`drag` 首帧原始 11.81%，
  但**居中对齐后仅 4.09%**（bbox 上移约 46px = "被拎起"的纯位移）。目标态 `drag` 的
  `FADE_MS` 为 0，硬切保住跟手的即时感 —— 任何溶解都会被读成"变慢/粘手"。
- QA（`avatar-sheet-tool.py verify`）：22 状态**无硬失败**；新增的软警告中 `drag_start`
  脚底偏离 30px 是刻意的离地姿势，已加入 `bottomExempt`；`attention` 举手时 8px 重心
  移动属真实素材细节，保留为软警告。

## 0. 一句话结论

本轮把这批 Q 版素材的 18 个状态接进状态机，每个状态都有明确入口、明确时长、明确落回，
并删掉已经和 `sleep_start` 语义重复的 `stretch`。没有新增兜底常量、没有留下
「配了但走不到」的分支。

**但必须先纠正一个容易搞错的前提**：旧状态机**并不**是"只有 7 个状态被用起来"。
HEAD 上 `PRIORITY` 已经覆盖全部 15 个 `AvatarState`，15 个状态**每个都有真实触发点**
（含 `stretch` 的 `scheduleStretch()`），`PetEmotion` 白名单也已经是 11 项、
`promptBuilder` 里 11 个情绪都写了使用语境。所以本轮的真正缺口是这四条，而不是"大面积死资产"：

| 真实缺口 | 说明 |
|---|---|
| **4 个新状态类型层根本不存在** | `head_tilt` / `sleep_start` / `sleep_end` / `drag` 不在 `AvatarState` 里，素材也没入库 |
| **`blink` 素材是错的** | 旧 `blink.png` 是 6.75 秒的"闭眼打瞌睡"，被当眨眼每 3–8 秒播一次 → 桌宠几乎一直闭眼 |
| **`drag` 没有视觉反馈** | 拖拽链路只发 IPC 移动窗口，`AvatarState` 里没有 `drag`，形象全程站姿被搬走 |
| **睡眠没有起/收动作** | 只有 `sleepy` 循环直接硬切，没有 `sleep_start` 入睡与 `sleep_end` 起床 |

`stretch` 的情况也要说准：它在 HEAD 上**是完整接通的**（有 `PRIORITY` / `FALLBACK_DUR` /
`scheduleStretch()` / `PetEmotion` 白名单 / 提示词条目 / `stretch.png`），
删它是因为**语义与新 `sleep_start` 重复**且**是旧画风不能混用**，
不是因为它是个半配置状态。详见 §3。

1. `PRIORITY` 与 `FALLBACK_DUR` 都是 `Record<AvatarState, …>` / 显式全量对象，

   + `wakeUp`）决定，不由优先级决定** —— 否则三段同层会互相挡住。

## 2. blink 处置：裁掉闭眼段，idle 只留清醒段

这是本轮唯一一个「语义判断 + 素材重剪」的取舍，拍板结论是
**「裁掉闭眼段做 blink，idle 只留清醒段」**。

### 2.1 为什么不能直接用源 idle 循环

源 `idle.png` 63 帧并非"站着呼吸"，逐帧实测（眼睛带内对齐后算暗像素占比）：

| 帧区间 | 眼睛暗像素占比 | 判读 |
|---|---|---|
| f0–f8 | 5.1%–6.6% | 睁眼站立 |
| **f9–f38** | **0.19%–0.37%** | **全闭 —— 这是一段 2.5 秒的「打瞌睡」** |
| f39 | 4.10% | 睁眼 |
| f40–f62 | 5.19%–6.6% | 睁眼站立 |

而且 f9–f38 不只是闭眼：腮红从 25.5% 涨到 32.2%、嘴微微张开 —— 那是"困了"的表情，
不是眨眼。把它当成 idle 的一部分，桌宠会每 5 秒犯一次困。

### 2.2 为什么 idle 做成乒乓剪辑而不是直接截断

剩下能用的清醒段是 f41–f62（22 帧），但这段**不是完美循环**：头部 `headY` 在 f41–f56 是
145、f57–f62 降到 144，即一次 1px 的单向沉降。直接首尾相接会跳：

| 循环方案 | 接缝 RMS | 接缝 SSIM | 说明 |
|---|---|---|---|
| 正放 f41–f62 后硬接回 f41 | 3.98 | 0.922 | 1px 沉降被吃掉，肉眼可见"顿一下" |
| **乒乓 f41→f62→f41（42 帧）** | **0.68** | — | 沉降变成一次呼吸，接缝低于表内相邻帧噪声 |
| 老皮肤 idle（127 帧） | 0.00 | 1.000 | 基准线 |

0.68 已经低于本表相邻帧的平均差异（0.49–2.60），等于"看不出来"。代价是呼吸节奏被迫
对称（吸/呼等长），对 22 帧的素材来说这点牺牲换来的是**零跳变**，值。

### 2.3 blink 的 6 帧怎么来的

源素材里单次眨眼被画成约 1.1 秒的慢动作（f16–f21 / f58–f62 两段全闭平台），
物理上不可能提快到 200ms，只能挑帧。最终取
`f41 → f9 → f13 → f39 → f40 → f41`（6 帧 @30fps = 200ms）：

- **首尾都落在 idle 循环的第 0 帧**（源 f41）→ 进出硬切零位移，切回 idle 不会跳；
- f9 / f13 取的是闭眼平台里眼睑最实的两帧，f39 / f40 是睁开过程；
- 30fps 整除 60Hz，逐帧驻留正好 2 个刷新周期，不会出现 1/2 交替抖动；
- 相邻帧 RMS 5.28 / 4.81 / 6.70 / 0.93 / 1.14 —— 中段 6.70 是"闭合"那一瞬，符合眨眼观感。

`durationOf('blink')` 由 `FALLBACK_DUR` 给 200ms，素材回填后是 `6/30*1000 = 200`，
两者一致，不存在"兜底值和真实时长打架"。

> 旧方案里 `avatar-spec.json` 记着一个 `blink_double.png` 的连眨变体（权重 3:1）。
> 渲染器没有 clip 级 `weight`，这个变体既无法执行、文件也已不存在 —— 本轮一并清掉了。

`stretch`（伸懒腰）在本轮被**从 `AvatarState` 中删除**，相关代码全部清空：

| 位置 | 处理 |
|---|---|

| `src/pet/avatar/SpriteRenderer.ts` | `FADE_MS.stretch` 删除 |
| `electron/ai/types.ts` | `PetEmotion` 去掉 `stretch`，加入 `head_tilt` |
| `electron/ai/reply/promptBuilder.ts` | 提示词条目 `stretch` → `head_tilt` |
| `resources/…/kirari/stretch.png` | **删除（git rm）** |

理由：新素材的 `sleep_start` 开头就是"打哈欠 + 坐下"，其中**前半段（f20–f55，约 1.5–2.3 秒）
是双臂举过头顶的伸懒腰 + 张嘴打哈欠**，而 `stretch` 原本的触发场景（随机伸个懒腰）
与它完全重叠。留着会有两个问题：

1. **两套画风**：旧 `stretch.png` 是 Q 版重做之前的素材（角色高、比例、线条都与新素材不同源），
   和新素材混播会明显跳画风。**不能复用**，这一点是硬约束。
2. **触发语义打架**：`sleep_start` 只能在入睡链里播（播完必须接 `sleepy`），
   `stretch` 却是个"随时可播的一次性动作"。同一个动作有两个入口、两套落回规则，
   就是典型的半配置状态。

> 素材核对（`_sleep_start_strip.png` 逐帧目视 + `_sleeptraj.py` 量包围盒）：
> `sleep_start` 是 **f0 站立 → f20–f55 伸懒腰打哈欠 → f65–f75 坐下 → f123 坐姿抱膝入睡**，
> 头顶从 79（与 idle 齐）降到 115、身高 388→352。所以它是"伸懒腰并睡下"，
> 不是单纯的"起身"。这也是它尾帧**必须**接 `sleepy` 而不能回 idle 的原因。

空出来的「互动语汇」由新素材 `head_tilt` 承担：对话框开着、你在当面说话时歪一下头，
表达"我在听呢"。它的触发选点见 §4.2。

## 4. 调度层的四处行为修正

### 4.1 睡眠链必须是独立链条，允许硬切

三段的姿态轨迹（`_sleeptraj.py` 逐帧量包围盒 + 目视）：

| 状态 | 首帧 | 尾帧 | 备注 |
|---|---|---|---|
| `sleep_start` | 站姿（头顶 79，与 idle 齐） | 坐姿抱膝（头顶 115，身高 388→352） | 中间 f20–f55 伸懒腰打哈欠 |
| `sleepy` | 趴桌（头顶 118） | 趴桌（循环） | 只有微幅呼吸 |
| `sleep_end` | 坐姿（头顶 117，接得上 `sleepy` 尾） | 站姿（头顶 70，比 idle 还高 10px） | 站起来后收势 |

所以链条是 **站 → (伸懒腰) → 坐 → 趴桌 → 坐 → 站**，`sleep_start` 的首尾**不是同一个姿态**。
`FADE_MS` 对 `sleep_start`/`sleep_end` 给 0（硬切入），`sleepy` 用默认 160ms（接住
`sleep_start` 尾帧那一跳，见 §4.5 的接缝表）。规则本身是：

- 入睡只发生在 `idle` 上（避免从说话/招手直接趴下）；
- 惊醒**必须**走 `sleep_end`，不能硬切 `idle` —— 否则会从趴着瞬间跳成站着；
- 强事件（说话 / 连接断开 / 报错 / 新消息）按设计**允许 hard cut 覆盖整条睡眠链**，
  此时不播 `sleep_end`：用户正在等反应，不能让 TA 先看 5 秒起床动画。

`wakeUp()` 的返回值和去重逻辑都收在这里：不在睡 → `false`；已在 `sleep_end` → `false`；
否则 `requestState('sleep_end', { force: true })` 并挂上"起床彩蛋"计时器，
计时器触发时再检查一次 `currentState === 'idle'`，避免彩蛋踩掉别的状态。

### 4.2 `head_tilt` vs `nod`：按对话框开合分流

`useChatSocket` 没有暴露"正在输入"的信号，所以拿不到真正的"键字中"。可用的最近信号是
**你发消息的那一刻**，于是按"是否当面"分流：

- 对话框**开着** → `head_tilt`（歪头倾听，冷却 20s，比 nod 长得多，避免每句都抽一下）
- 对话框**关着** → `nod`（远远听到一句，点个头，冷却 1.5s）

两者都走 `tryGesture()`，天然受优先级与睡眠保护约束。

### 4.3 `drag` 进入时机：要真的动了才算

原先的实现是 `pointerdown` 就切 `drag`，结果是**一次轻点也会先闪一帧"被拎起来"的姿势**，
再跳去 `handleTap()` 的表情。现在拆成两步：

- `pointerdown` → 只做预备（`setPointerCapture`、上报 `drag-start`、叫醒、重置闲置计时）；
- 第一次 `pointermove` → 才真正 `enterDragState()`（切 `drag` + 冒"跟着你移动中"），
  并清掉一次性动作的收尾计时器，否则它到点会把 `drag` 顶成 `idle`；
- `pointerup` 且全程没移动 → 走 `handleTap()`，不进 `drag`，也不说拖拽台词；
- `pointerup` 且移动过 → 恢复：`speak` 直接 `setState('speak')` + `armSpeakTail()`
  （**不能**走 `playSpeak()`，会被自己的优先级挡住，见 §4.4），其余一律 `idle`。

`drag` 期间的非 `drag` 状态请求被 `requestState()` 显式拦截（不只是靠优先级数值），
所以将来调优先级也不会误放行。

### 4.4 两个「计时器打架」的坑（一个既有、一个本轮自己踩的）

都属于"优先级 + 计时器"组合出来的问题，写出来是因为它们**不会报错，只会让画面莫名停在某帧**，
是最难靠 review 发现的一类。

1. **【既有】情绪没抢到也照样等 5 秒。** `playEmotionThenSpeak()` 原先是
   "`requestState(emo)` → 无条件按情绪时长排一个接说话的计时器"。
   如果请求被更高优先级挡掉（比如已经在 `speak`，或正在 `thinking`），
   屏幕上根本没有情绪动作，回复却要白等 5 秒才出现。HEAD 上就是这个行为。
   现在改成 **`requestState(emo)` 返回 `false` 就立刻 `playSpeak()`**，不排空档；
   成功时再把"`requestState` 已挂的回 idle 计时器"显式撤掉再挂接说话，避免两个计时器同时开火。

2. **【本轮引入并已修】松手恢复 `speak` 会被 `drag` 自己的优先级挡住。**
   重写 `stopDrag()` 时先写成了调 `playSpeak()`，而 `playSpeak()` 内部走 `requestState`，
   此刻 `currentState` 还是 `drag`（优先级 200）→ 直接返回 `false`，
   说话既没切过去、也没挂回 idle 计时器，桌宠就僵在 `drag` 末帧。
   HEAD 上不存在这条路径（`drag` 状态是本轮才加进 `AvatarState` 的）。
   修法：把 `speak` 的收尾计时器抽成 `armSpeakTail()`，`stopDrag()` 直接
   `avatarStore.setState('speak')` + `armSpeakTail()`，绕过优先级检查同时补齐计时器。

> 教训（写进交接）：**`requestState()` 是唯一带优先级闸门的入口，
> 任何"我已经确定要切这个状态"的收尾/恢复路径都不该再走它**，
> 否则会跟闸门自己打架。新增这类路径时要么 `setState` 直切 + 自己挂计时器，
> 要么给 `requestState` 传 `{ force: true }` 并说明理由。

### 4.5 接缝实测：哪些溶解时长是有依据的，哪些不是

`FADE_MS` 的数值不是拍脑袋定的。用**预乘 RGB + alpha 的平均绝对差**（0–100%，
和 `build-transition-frames.cjs` 同口径）把所有会相邻播放的帧对量了一遍，
判据是"该表的 p95 相邻帧步长" —— 接缝差异不超过它，硬切就只相当于多播一帧，看不出来。

| 接缝 | 差异 | 目标态溶解 | 该表 p95 帧步长 | 结论 |
|---|---|---|---|---|
| `idle` ↔ `blink` | 0.20% / 0.00% | 160ms | idle 0.37% | 优（blink 首尾帧就是 idle 首帧） |
| `idle` → `sleep_start` | 3.33% | **0ms** | sleep_start 5.61% | 可（低于该表 p95，硬切≈多播一帧） |
| `sleep_start` → `sleepy` | 3.27% | 160ms | sleepy 1.05% | 可（超 p95，靠 sleepy 的溶解盖） |
| `sleepy` → `sleep_end` | 2.40% | **0ms** | sleep_end 3.44% | 可（2.40 < 3.44，硬切≈多播一帧） |
| `sleep_end` → `idle` | **4.87%** | → **220ms** | idle 0.37% | **原本会顿挫，已调长** |
| `idle` → `drag` | 15.90% | **0ms** | — | **不是缺陷**：居中后残差仅 2.87%，是纯整体位移（dy=−65px 被拎起） |
| `drag` → `idle` | 15.83% | 220ms | — | 同上，纯位移（dy=+67px 放下） |
| 11 个一次性动作 入/退场 | 1.40%–2.41% | 160–200ms | — | 全部优，**不需要** `build-transition-frames.cjs` |

注意判据是**目标态**的 p95 步长，不是笼统的百分比阈值。同一个 3.27%，落到
`sleepy`（噪声 p95 仅 1.05%、趴在桌上几乎不动）就是"明显一跳"，落到
`sleep_start`（p95 5.61%、本来就在大幅起身）就"看不出来"。所以
`FADE_MS` 挂 target 而不是 source 是对的（渲染器 L326 `FADE_MS[target] ?? 160`）。

两条重要修正：
1. **`drag` 的 15.9% 不是问题。** 素材 `drag` 整帧被抬高 65–71px（脚离地），
   按内容包围盒对齐后残差只有 2.7%，和 idle 自身呼吸抖动同量级 ——
   硬切时的"跳"会被"窗口正在跟着鼠标动"完全掩蔽。所以 `FADE_MS.drag = 0` 是对的。
2. **`sleep_end → idle` 原本 4.87% 配 160ms 会顿挫** → `FADE_MS.idle` 提到 **220ms**。
   这是本轮唯一因为实测而改的溶解时长（只影响"回到 idle"这一族，其余切换不取该值）。

## 7. 已知问题（本轮不修，需要单独立项）

### 7.1 24fps 除不尽 60Hz（拍板：先不动素材）

新素材一次性动作全是 24fps，`60/24 = 2.5` → 渲染器 `acc += dt` 的累加逻辑会让**每帧驻留
在 2 个和 3 个刷新周期之间交替**，严格说是不均匀的（12/15/20/30fps 才整除 60）。
这个交替是**存在但不可见**的：2 周期≈33.3ms、3 周期=50ms，差 16.7ms，
在 24fps 的动作里相当于画面内部本来就有的步长波动 —— 实测没有可感知的抖动。

同期还有一个更明显的问题：**一次性动作时长 4.03–5.17 秒**，而规格卡目标是 1.2–2.5 秒。
慢放感主要来自"动作时长 vs 目标时长"，不是帧率。**拍板结论是「先不动素材，24fps 原样接入」**，
重定时（`retime`）留到下一轮，届时改 `avatar-spec.json` 把对应状态从 `keep` 改成
`retime`（`targetSec` + `pad`）即可，不用改代码。

### 7.2 `hitTest` 的逐像素性能瓶颈（不重构，仅记录）

`SpriteRenderer.hitTest()` 每次调用都 `getImageData(1, 1)` 读单个像素，而
`desktop-pet:cursor` 轮询是**每 20ms 一次**（主进程 `setInterval`）→ 每秒 50 次
`getImageData`，每次都会打断 canvas 的 GPU 管线（readback 同步等待）。

现在能跑是因为 1×1 的 readback 足够小，但这是本组件最脆的一环：
窗口再大、或者将来要支持多像素软命中，就必须改成"离屏 canvas 一次读取整帧 alpha 到
`Uint8ClampedArray`，命中测试查表"。**本轮按交接要求不动它**（属于坐标/绘制红线附近，
且与状态机无关），只在此备案。

### 7.3 质检软警告 31 条（素材本身，不阻塞）

`python scripts/avatar-sheet-tool.py verify` 输出 31 条警告、**硬失败 0**。分三类：

1. **首/尾帧 vs 锚图 SSIM < 0.95**（21 条）：一次性动作的首帧是"动作起点"而非标准站姿，
   这是设计如此（`drag` 首帧就是被拎起、`sleep_start` 首帧是起身），不是缺陷。
2. **相邻帧跳变 RMS > 40**（多状态）：AI 视频抽帧的固有抖动，`happy` 起跳/落地、
   `excited` 蹦跳处最明显。消除只能重生成。
3. **`drag` 循环接缝 SSIM 0.921**（< 0.95）：拖拽时人眼只关注跟手，可接受。

### 7.4 顺带查出的既有问题：`personality` 台词库**加载了但没人读**

这条不属于状态机，但违反了「不留死配置」的同一条原则，必须写出来而不能假装没看见。

`SpriteRenderer.load()` 在读到 `frames.json.personality` 时会
`dialogueManager.loadPersonality(...)`，但 `dialogueManager` 的**两个对外方法
（`getDialogue()` / `getOnEquipReaction()`）全仓库零调用**——HEAD 上就是零调用，
不是本轮引入的。实机上桌宠泡泡里的文字来自 `petStore.setMessage()`，
在 `PetStage.vue` 里只有两处硬编码（`'跟着你移动中。'` / `'这里看起来不错。'`），
和 `personality` 无关。

所以现在 `frames.json` 里那 17 个台词键（含本轮新写的 `head_tilt`）
**在运行时完全不生效**。本轮的处理是：

- **没有**为了让块"看起来完整"而补 `happy` / `wave` 的台词 —— 往一个没人读的块里加键
  才是真正的「配了但走不到」。HEAD 的块同样没有这两个键，本轮只是等量搬迁（`stretch`→`head_tilt`）。
- 已经校验的是**格式合法性**：17 个键全部是 `PersonalityDialogues` 的合法成员，
  `drag` 有 `start`/`end` 两个非空数组，`onEquip.emotion = "wave"` 是合法 `AvatarState`。
  这样将来真去接线时不需要先修数据。
- 接线的做法有两种，**都要先在 `PetStage` 里立一个出口**（例如把两处硬编码换成
  `dialogueManager.getDialogue('drag', 'start')`），属独立一轮的活，本轮未做。

> 如果决定不要这条线，正确做法是**连着 `PersonalityDialogues`、
> `dialogueManager.ts`、`frames.json.personality`、`RESERVED_KEYS` 里的 `"personality"`
> 一起删干净**，而不是只删数据留类型。别只删一半。
