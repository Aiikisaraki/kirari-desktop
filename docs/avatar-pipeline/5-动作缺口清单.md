# 5. 动作缺口清单

> 按**触发情境**分类，不是按情绪分类 —— 因为桌宠的观感来自「什么场合它做了什么」，
> 而不是「它一共有几种情绪」。
>
> 标记说明：
> - **必须新增** = 现有素材 + 变体都替代不了，只能画
> - **可用变体** = 现有素材翻转/倒放/变速/组合就能出，零成本
> - **可用现有+文字** = 动作可以不做，用气泡台词顶上

## 5.1 待机 / 环境（无人操作时的存在感）

| 情境 | 现状 | 缺口 | 分类 | 优先级 |
|---|---|---|---|---|
| 长时间闲置 → 打瞌睡 | `sleepy` 一个循环表在冒充「入睡 + 睡觉 + 醒来」 | 三段接力：`sleep_start` / `sleep_loop` / `sleep_end` | **必须新增** | **P0** |
| 刚睡着的过渡 | 直接切到 `sleepy` 循环，会硬跳 | `sleep_start`（打哈欠→眼皮沉→坐下蜷缩） | **必须新增** | **P0** |
| 被打扰唤醒 | 直接切回 `idle`，像「瞬间清醒」 | `sleep_end`（睁眼→撑地→伸懒腰→站起） | **必须新增** | **P0** |
| 打哈欠 | 复用 `stretch`（伸懒腰）勉强算 | 可用 `sleep_start` 的前 1.5 秒单独切一段 | 可用变体 | P1 |
| 看向另一边 | 只能正脸 | `wave` / `thinking` / `shy` 水平翻转 | 可用变体 | P1 |
| 整理衣角 / 理头发 | 无 | 「活人感」最强的小动作，只有 1~2 秒 | **必须新增** | P1 |
| 起身走两步换个位置 | **完全没有**。只有被拖动才会移动 | 走/转身 + 主进程移动窗口（`setPosition` 缓动） | **必须新增** + 代码 | P2 |
| 蹲下 / 坐下 | 无 | 可用 `sleep_loop` 首段 + 文字 | 可用变体 | P2 |

## 5.2 交互反馈（用户动手之后）

| 情境 | 现状 | 缺口 | 分类 | 优先级 |
|---|---|---|---|---|
| 单击一下 | **没有专用反应**（要连点 3 次才 `happy`） | 被点时的轻微反应（缩一下肩 / 转头看） | 可用 `surprised` 1.4s + 文字 | P1 |
| 被拖起来（悬空） | 只有气泡「跟着你移动中。」，形象仍是站立 | 悬空姿态：脚离地、手臂下垂、轻微摆动 | **必须新增** | **P0** |
| 被放下 | 无 | `stretch` 倒放（松下来） | 可用变体 | P1 |
| 抚摸 | `shy` 已覆盖 | — | 已有 | — |
| 反复抚摸 / 揉脸 | 只会一直害羞，没有「够了」的反馈 | 生气 / 不满（鼓腮、抱臂、头转开） | **必须新增** | **P0** |
| 右键菜单 | 无反应 | 可用 `nod` + 文字 | 可用现有+文字 | P2 |

## 5.3 对话

| 情境 | 现状 | 缺口 | 分类 | 优先级 |
|---|---|---|---|---|
| 说话中 | `speak`（8fps 循环） | — | 已有 | — |
| 等待回复 | `thinking`（2.4s 循环重播） | — | 已有（阶段 0 提速） | — |
| **听用户说话** | 无。用户发消息只 `nod` 一下 | 歪头倾听（`head_tilt`）—— 对话里最提升「在听」观感的动作 | **必须新增** | **P0** |
| 听不懂 / 没听清 | 无 | 歪头 + 眨眼 + 气泡「欸？」 | 可用 `thinking` + 文字 | P1 |
| 道歉 / 不好意思 | 无 | `bow`（鞠躬）够用 | 可用现有+文字 | P2 |
| 说再见 | `wave` | — | 已有 | — |

## 5.4 情绪

| 情绪 | 素材 | 缺口 | 分类 | 优先级 |
|---|---|---|---|---|
| 高兴 `happy` | 有 | — | — | — |
| 伤心 `sad` | 有 | — | — | — |
| 兴奋 `excited` | 有 | — | — | — |
| 惊讶 `surprised` | 有 | — | — | — |
| 害羞 `shy` | 有 | — | — | — |
| 思考 `thinking` | 有 | — | — | — |
| **生气 / 不满** | **无** | 在「一直摸它」「要求做不到」时会用 | **必须新增** | **P0** |
| 委屈 / 快哭了 | 无 | `sad` 只表达低落，没有「被欺负」 | **必须新增** | P1 |
| 得意 / 骄傲 | 无 | `happy` 1.3x + 文字 | 可用变体 | P2 |
| 无语 / 汗颜 | 无 | 气泡「……」+ `shake` | 可用现有+文字 | P2 |
| 困倦 | `sleepy` 前段 | `idle` 0.7x + 文字 | 可用变体 | P2 |

## 5.5 系统 / 协议事件

| 情境 | 现状 | 缺口 | 分类 | 优先级 |
|---|---|---|---|---|
| 连接成功 | `excited` | — | 已有 | — |
| 连接断开 | `sad` | — | 已有 | — |
| 出错 | `shake` | — | 已有 | — |
| 收到新消息（对话框关着） | `surprised` | — | 已有 | — |
| 收到图片 | 无动作 | 可用 `surprised` + 气泡「让我看看」 | 可用现有+文字 | P2 |
| **定时提醒 / 待办到点** | 无。现在只能靠气泡 | 举手引起注意（`attention`：抬手挥两下 + 看向用户） | **必须新增** | P1 |
| 被叫名字 | 无 | `nod` + 文字 | 可用现有+文字 | P2 |

## 5.6 时间 / 场景

| 情境 | 现状 | 缺口 | 分类 | 优先级 |
|---|---|---|---|---|
| 早安 | 无 | `wave` + `bow` 组合链 + 气泡 | 可用变体 | P1 |
| 晚安 | 无 | `sleep_start` + 气泡 | 可用变体 | P1 |
| 深夜 | `sleepy` | — | 已有 | — |
| 长时间没人理 | `sleepy` | `stretch` / 理头发已够 | 已有 | — |
| 节日 / 生日彩蛋 | 无 | 一次性特殊动作（戴帽子等） | **必须新增** | P3 |

## 5.7 汇总：按优先级排的采购单

**P0（4 个动作，全部「必须新增」）**

| # | 动作 | 为什么是 P0 |
|---|---|---|
| 1 | `sleep_start` | 现在睡觉是「循环表冒充」，硬跳最明显 |
| 2 | `sleep_end` | 同上 |
| 3 | `drag`（悬空，**需两条**：`drag_start` 过渡 + `drag_loop` 循环） | 拖动是最高频交互，形象完全不配合 → 违和感最强。只做一条的话，拖超过 5 秒就僵在末帧 |
| 4 | `head_tilt`（歪头倾听） | 对话场景里最缺的「在听」反馈 |
| 5 | `angry`（生气） | 唯一的负反馈出口，没有它「摸烦了」只能一直害羞 |

**P1（7 个，4 个必须新增 + 3 个可用变体）**
`sleep_loop`（其实可复用 `sleepy`）、整理衣角、被点反应、attention、委屈、早安/晚安链、看向另一边（翻转）

**P2/P3（可延后）**
走两步换位置（要动主进程窗口移动）、蹲下、得意、无语、节日彩蛋

## 5.8 素材采购的批次建议

一次生成一条视频的边际成本不低，按「一条视频能覆盖几个状态」组批：

| 批次 | 生成条目 | 覆盖状态 | 说明 |
|---|---|---|---|
| 批次 1 | `sleep_start` + `sleep_end` | 2 | 同一条地面线、同一睡姿，必须一起做 |
| 批次 2 | `drag_start` + `drag_loop` | 2 | 悬空姿态要单独设计（脚离地、底边不落地），只能单做；两条一起出图，衔接才对得上 |
| 批次 3 | `head_tilt` + `angry` + `tidy`（理衣角） | 3 | 都是 1~2 秒的地面小动作，共用同一套首尾锚图 |
| 批次 4 | `attention`（举手） | 1 | 幅度大，单独做 |
| 批次 5 | `cry`（委屈） | 1 | 情绪类，单独做 |

每批都先做**标准站立锚图**（文生图），确认这张图之后再拿它当首尾帧去生成 —— 一张锚图
是所有动作的共同基准，锚图错了整批都要重来。
