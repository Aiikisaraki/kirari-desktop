# 2. 重剪与质检

工具：`scripts/avatar-sheet-tool.py`（Python 3 + Pillow + numpy）
规格：`scripts/avatar-spec.json`（数据驱动，改时长不用改脚本）

设计前提：**默认只读**。不加 `--write` 什么都不动，加 `--write` 先整目录备份再改。

## 2.0 入库全流程（新素材走这条）

```bash
# 1) 抽帧（只抽 RGB，不要用 ffmpeg 的 chromakey —— 理由见下）
ffmpeg -i sleep_loop.mp4 -vf "fps=12" -vsync 0 tmp/sleep_rgb/f%04d.png

# 2) 抠像：按「绿度」做软 alpha（0=不透明 999）
python scripts/avatar-sheet-tool.py key --from tmp/sleep_rgb --to tmp/sleep_key --write

# 3) 清残留（必做，豆包的绿幕素材几乎一定带软阴影 + 角落水印）
python scripts/avatar-sheet-tool.py clean --from tmp/sleep_key --to tmp/sleep_clean --write

# 4) 入库（坐/躺/悬空用 --scale-by face；站姿动作用默认 height）
python scripts/avatar-sheet-tool.py pack --from tmp/sleep_clean --state sleepy \
  --fps 12 --loop --loop-crossfade 2 --scale-by face --write

# 5) 质检
python scripts/avatar-sheet-tool.py verify
```

**为什么不用 `chromakey`**：它算的是"到某个绿的距离"，参数一紧，抗锯齿边缘就在"算前景/算背景"
之间逐帧翻面。本项目绿幕的可分性极好（实测背景 E=223、绿幕上的软阴影 E=226、头发 E=−19、
白衬衫 E=−11，其中 E = G − max(R,B)），直接按 E 做线性 alpha 更稳，而且**软阴影天生就是绿的，
会被同一个判据吃掉**。

**入库前先量「全片首帧 vs 尾帧 SSIM」，再决定要不要截断**（2026-11-03 踩过）：

| 首↔尾 SSIM | 含义 | 怎么处理 |
|---|---|---|
| ≥ 0.93 | 视频**自己首尾闭合**（happy 实测 0.954） | **整条用**，不要截断、也不要加 `--tail-anchor` |
| 0.85~0.93 | 大致回到站姿 | 直接用 |
| < 0.85 | 确实没画回站姿 | 才考虑截掉多余段 + `--tail-anchor N` 补渐变 |

我一开始只看"跳完还有 2.5 秒"就截断了 happy，结果截在"双手捧胸、眼睛闭着"那一帧，
再强行补渐变 —— 既丢了自然收尾又做出叠影。**先量，再决定。**

**`smooth` 是可选步骤，本项目默认不开**：它能压掉 AI 逐帧重画明暗带来的高频抖动
（实测二阶差分 p99 从 74.7 → 46.3/35.3），但也会把呼吸这类细微变化压平。
2026-11-03 实测三档对照后，用户选**不滤波**。要开就插在 `clean` 之后：
`python scripts/avatar-sheet-tool.py smooth --from tmp/sleep_clean --to tmp/sleep_smooth --radius 2 --write`

`clean` 的两条判据（缺一不可，实测各治一种残留）：

| 判据 | 治什么 | 为什么 |
|---|---|---|
| 只保留**面积最大的连通域** | 水印、图标、杂物 | 豆包水印是半透明小字，常散成 3~4 个独立小块，且**位置会在帧间跳**（有的帧在右下角、有的帧在左上角） |
| 只保留**贴着不透明主体 1px** 的像素 | 绿幕上的软阴影 | 阴影和鞋是连着的，连通域分不开；但它不是贴着轮廓的细边，而是散开一大片 |

> 实测：`sleep_loop.mp4` 未清理时包围盒被"投影+水印"撑到占画幅 **96%**、逐帧上界抖动 183px；
> 清理后是 **63%**、抖动 1~12px。**先清再量，否则所有占位/尺寸判断都会被带偏。**

## 2.1 四条命令

在仓库根目录跑（Git Bash / PowerShell 都行，路径用正斜杠最省事）：

```bash
# 1) 体检：每状态帧数/fps/时长/首尾锚定/活动区间
python scripts/avatar-sheet-tool.py analyze

# 2) 预演：如果 --write 会改成什么样（前后对照表），不写盘
python scripts/avatar-sheet-tool.py plan

# 3) 落盘：备份 → 重剪 PNG → 回写 frames.json → 自动跑一遍质检
python scripts/avatar-sheet-tool.py apply --write

# 4) 质检：硬失败退出码 1，可挂 CI
python scripts/avatar-sheet-tool.py verify

# 5) 回滚：整目录还原到某次备份
python scripts/avatar-sheet-tool.py restore .avatar-backup/20261102-012806

# 只在沙盒里试（不动真素材）
python scripts/avatar-sheet-tool.py apply --write --skin /tmp/kirari-copy
```

## 2.2 `avatar-spec.json` 字段

```jsonc
{
  "anchor": { "state": "idle", "frame": 0 },   // 锚图：所有一次性动作首尾应对齐它
  "states": {
    "wave": {
      "mode": "retime",        // keep | retime | trim
      "trigger": "悬浮 1s",     // 只作文档用途
      "targetSec": 2.0         // retime：目标时长（fps = frames/targetSec）
    },
    "blink": {
      "mode": "trim",
      "targetSec": 0.29,
      "clips": [               // trim：每个输出变体一条
        {
          "src": 0,                            // 从源的第几个变体裁（多个输出可共用一个源）
          "sheet": "blink.png",                // 输出文件名（可与源同名 = 原地替换）
          "pick": [0, 14, 19, 26],             // 取源的第几帧（人眼+实测确认过的帧号）
          "fps": 14,
          "weight": 3                          // 可选：变体权重，缺省等概率
        },
        { "src": 0, "sheet": "blink_double.png", "pick": [0,14,19,26,55,61,68], "fps": 12, "weight": 1 }
      ]
    },
    "excited": { "mode": "retime", "targetSec": 2.0, "anchorTail": 3 }
  }
}
```

- `anchorTail: N`（可选）：末尾追加 N 帧，从中途渐变到锚图、最后一帧就是锚图本身。
  用于尾帧停在「张开手臂」这类不回站姿的动作（`excited` / `shy` / `stretch`）。
  追加帧 = 溶解过渡，0.1s 内看不出鬼影，比硬切自然。默认 0 = 关。
  追加过的帧数会记进 `frames.json` 的 `_anchorTail`，所以 `apply` 可以重复执行，不会一直加帧。
- `pad: N`（可选，**必看**）：不计入动作时长的过渡帧数。`fps = (frames - pad) / targetSec`。
  `scripts/build-transition-frames.cjs`（2026-10-11）给 **bow / excited / nod / sad / shake /
  shy / stretch / surprised / thinking 各插了 4 进 4 出**共 8 帧（为了消除硬切闪入），
  这 8 帧不是动作本体。不扣掉的话，每个动作会被多提快 16%。
  例：`nod` 表里 57 帧、其中 8 帧过渡 → 有效 49 帧 → `49 / 1.2 = 40.8fps`（正是规格卡的数）。
  这 8 帧的属性只能靠人确认（自动检测会被"站立微漂"骗），所以写在 spec 里，不让脚本猜。
- `trim` 的 `pick` 是**人工确认的帧号**，脚本不做语义猜测——自动差异曲线不可靠
  （`blink` 的自动活动区间是 f3~f74，等于全片，因为站立微漂也会产生差异）。

## 2.3 质检判据

分两档。**硬失败**会让桌宠真的出问题，**警告**只表示素材不够理想。

| 档 | 检查 | 阈值 | 为什么 |
|---|---|---|---|
| 硬 | 全帧透明 | alpha max == 0 | 画出来什么都没有，还会导致整窗点穿 |
| 硬 | 帧尺寸与声明不符 | 严格相等 | `drawImage` 会切错位 |
| 硬 | 绿幕残留 | 实心像素里「近纯绿」占比 > 1% | 抠像漏了最常见的废稿特征 |
| 软 | 角色高度偏差 | 中位高与锚图差 > 8% | 生成时角色被放大/缩小 |
| 软 | 首/尾回锚 | SSIM < 0.95（loop 态看首尾互相） | 切回 idle 会跳姿势 |
| 软 | 脚底基线偏移 | \|bottom - 473\| > 4px | 会看到「脚陷进地里」 |
| 软 | 相邻帧跳变 | RMS > 40 | 重剪拼接或丢帧产生突变 |

**为什么「首尾回锚」只算警告**：存量 15 个动作是 15 个不同生成批次，
同一个「标准站姿」渲染细节就不同（实测 `nod` 首帧与 idle 锚图 SSIM 仅 0.906，
几何却完全一致）。这个阈值只对**新生成**素材（同一模型同一条提示词）有约束力。
等阶段 1 的锚图管线跑起来后，可以把它提成硬失败。

## 2.4 备份与回滚

- 每次 `apply --write` 都会把整个皮肤目录复制到 `.avatar-backup/<YYYYmmdd-HHMMSS>/kirari/`
  并写一份 `backup.json`（时间、皮肤路径、原因）。
- 还原：`restore .avatar-backup/<时间戳>`
- `.avatar-backup/` 要加进 `.gitignore`（一份备份 ≈ 66 MB）。

## 2.5 已知限制

1. **不能自动判语义**。「这个动作在第几帧结束」必须人眼看。工具只负责按给定的帧号执行，
   以及事后用它自己的度量（SSIM / 包围盒 / 绿幕）把不合格的素材拦下来。
2. **变速没有上限保护**。`targetSec` 填得过小会让动作变成抽搐；脚本只 clamp 到 60fps，
   节奏是否自然要在 dev 里看。
3. **不支持缩放归一**。若新素材的角色比例和锚图差超过 8%（`targets` 里的期望值），
   工具只报警、不自动缩放——缩放会糊掉线稿，宁可退回重新生成。
4. **不改代码**。工具只碰 `frames.json` 与 PNG。`FALLBACK_DUR` 之类的兜底常量要手工同步。

## 2.6 2026-11-03 重写版的行为约定

工具在 11-03 被重写过一次（上一版的脚本随沙盒丢失）。重写时补了四条约定，都在实机上验过：

| 约定 | 为什么 |
|---|---|
| **`apply` 可重复执行** | 已经等于目标值的 fps、已经裁成 `len(picks)` 帧的输出表 → 标 `已是最新，跳过`；全部跳过时直接返回，不写盘、不备份、不动 `version` |
| **`--backup-dir`** | 默认仍是仓库根 `.avatar-backup/`；在沙盒副本上试跑时把备份放到仓库外，避免 66 MB 备份混进仓库 |
| **同名源表先读后写** | `blink` 的两个变体共用 `blink.png` 当源。边写边读会让第二个变体读到已被裁成 4 帧的表（首版实测 6 帧全透明） |
| **`restore` 默认不删多出来的文件** | 备份里没有的文件（如 `blink_double.png`）默认保留并提示，加 `--prune` 才删 |
| **`--auto-trim` 改用「与末帧的相似度」判定** | 逐帧差分会被打包时的重采样抖动打断（wave 末段有个 1.71 的噪声尖峰，13 帧尾巴只切掉 5 帧）。改成 `rms(帧, 末帧) < staticRms`，`staticRms` 从 1.5 提到 **4.0**（AI 视频的"静止"其实有 2~4 的缓慢沉降） |
| **`pack --loop-crossfade N`** | AI 做不到首尾逐帧一致：speak 不做收尾时循环接缝 SSIM 只有 0.853，每圈嘴型跳一下；追加 2 帧渐变后 0.985 |
| **帧率提示** | fps 除不尽 60Hz 时 `pack` 会提醒（渲染端 dt 累加器会让每帧驻留摆动） |
| **`key` 子命令** | 按绿度做软 alpha（默认 lo=60 hi=140）+ 去绿溢。替代 ffmpeg 的 chromakey，边缘不翻面 |
| **`smooth` 子命令** | 时间轴中位数去闪，治"AI 每帧重画明暗"。**默认不开**（会把呼吸压平），实测三档对照后选定不滤波 |
| **`clean` 子命令** | 抠像之后必做一步：连通域去水印/杂物 + 贴核心判据去软阴影。见 2.0 |
| **`--scale-by face`** | 坐/躺/悬空的姿势必须按**脸宽**归一化；头宽会被散开的头发带偏，身高会让人变大 |
| **`--scale N`** | 直接指定缩放系数，覆盖 `--scale-by`（手工微调用） |
| **`--lift N`** | 整体上移 N 像素。**悬空素材（`drag`）必须用**：默认会把底边对齐锚图脚底线 468，不抬就等于"踮脚站在地上"。实测 `--lift 70` → 底边 398 |
| **`--tail-anchor N`** | 一次性动作尾部追加 N 帧渐变回锚图（末帧=锚图）。AI 几乎从不把最后几帧画回标准站姿（happy 跳完双手一直捧在胸前），不加这个，切回 idle 会跳姿势 |
| **`--loop-crossfade N`** | 循环态尾部追加 N 帧「末帧→首帧」渐变，消掉循环接缝的顿挫 |
| **杂物检测只看四角** | 水印/杂块都在画幅四角；跳跃、举手会让角色合法地冲出站姿包围盒（happy 起跳时头顶高 111px），按"全幅越界"判会误报 |
| **`targets.heightExempt`** | 这些状态不参与"角色高 vs 锚图 390px"的软检查（坐/躺/悬空天生更矮或更高）。当前皮肤为 sleepy/sleep_start/sleep_end/drag |
| **`targets.bottomExempt`** | 这些状态不参与"脚底 y vs 锚图脚底线"的软检查。**被拎起来的 `drag` 必须列入**：实测它的脚底在 y=397，与站姿的 469 差 72px —— 那不是对齐错误，是"脚离地"这件事本身（见 `--lift`）。不列会永远报一条假警告 |

沙盒副本上的实测结果（2026-11-03，`--skin` 指向临时副本）：

```
apply --write   →  13 段：blink 81→4+7 帧，11 个动作 fps 12→20.3~40.8
verify          →  无硬失败；4 条软警告
                    blink/blink.png 尾帧回锚 0.935（4 帧短变体，睁眼帧与锚图本就差 0.965）
                    happy 2 处帧间跳变（f25/f26，跳起落地）
                    excited 尾帧回锚 0.949、9 处帧间跳变
```

> 注意：这 4 条警告在**原始素材**上就存在（`verify` 在未 apply 的皮肤上同样报），
> 不是重剪引入的。想消掉只能重生成。
